# Be Myself · 人生之书

## 1. 产品定义

Be Myself 是一款 5—7 分钟的单人交互数字艺术游戏。玩家扮演“林”，穿过五个年龄切片，在每个切片中完成同一组动作：说出心愿、看见处境、做出行动、承担结果。游戏最终把玩家自己的选择变成一张可保存的“人生书页”。

核心命题是：

> 我以为是自己的选择，有多少其实是别人替我写好的？

游戏不对玩家进行人格评分，不给出最优结局，也不把资源差异解释成个人能力差异。它的价值来自让玩家同时看见主体性、关系和结构条件。

## 2. 体验目标

玩家离开游戏时应当带走三种感受：

1. 我曾经亲手做过选择，而不是只读了一段故事。
2. 一个选择有愿望，也有成本；成本不必被伪装成失败。
3. 我可以回看、协商并重新写下一笔。

叙事还要回答一个更难的问题：如果玩家真的每一次都顺着自己的心意走，这条路会把他带到哪里？他会喜欢那里的风景吗？因此游戏不能只揭示“谁替我写下了选择”，还必须让玩家亲自走一遍“心愿路线”，看见它获得什么、失去什么，以及哪些价格没有写在标签上。

作品的价值观不是“永远坚持自己”，而是：选择没有对错；每个选择都有代价，也有独特的风景；关键在于它是否经过思考、是否由玩家自主做出。放手可以是自主，承担也可以是自主。玩家要么放手，要么找到那个没有在标签上写明的价格，并决定是否支付它。

视觉、声音和交互都服务于这三个感受。所有动效都应当有叙事含义，避免为了炫技增加噪音。

## 3. 核心循环

```text
心愿
  ↓
现实条件显影
  ↓
行动
  ↓
得到与代价
  ↓
留下视觉痕迹
  ↓
翻到人生背面
  ↓
显影隐藏笔迹 / 重写一页
```

### 3.1 第一遍：只问心愿

玩家先从内在愿望出发，选择最想要的方向。此时不展示资源、家庭或制度条件，保护直觉的完整性。

### 3.2 第二遍：把现实放回画面

游戏展示同一时刻的关系压力和资源条件，玩家重新选择行动。第一遍和第二遍可以相同，也可以不同。差异本身就是叙事结果。

### 3.3 这一页：呈现结果

每个行动同时呈现获得与承担。游戏不把结果包装成奖励或惩罚，而是把选择的复杂性写回页面。

### 3.4 背面：显影与重写

完成五个时刻后，玩家看到心愿与行动的并排记录，点击显影后看到选项背后的结构性笔迹。玩家可重写任意一页，并比较两个版本留下的不同结果。

显影后会出现“如果完全按心意走”路线。它逐章展示玩家第一遍选择的愿望将带来的获得与代价，再提出一个开放问题：这会是玩家喜欢的结果吗？这条路线没有被标记为正确答案，它只是把“做自己”从口号变成可以被体验、被检验、被承担的生活。

## 4. 视觉系统

### 4.1 视觉隐喻

- 纸张：人生仍在书写，页面可以被翻到背面。
- 红线：期待、义务、评价和关系施加的牵引。
- 人形纸片：主体不是空白，也不是固定人格，而是在条件中逐渐形成。
- 网格与档案标记：制度、时间和社会结构进入私人故事。
- 墨迹与显影：玩家的决定不会被覆盖，隐藏作者会逐步出现。

### 4.2 视觉原则

- 版式先于特效：中文长文本必须保持阅读节奏。
- 动效要有因果：线条松开表示空间改变，显影表示理解增加。
- 颜色不代表善恶：不同阶段拥有不同色温，只用来区分情境。
- 留白是交互的一部分：让玩家在选择之后有停顿和回响。
- 移动端优先：所有核心交互使用 Pointer Events，避免只依赖 hover。

## 5. 交互与游戏机制

当前第一版采用可访问的按钮交互，下一阶段逐步加入身体化操作：

1. 拖动红线：玩家把牵引线拖向“继续承担”或“暂时松开”。
2. 长按显影：隐藏文字在持续按压中出现，松手后停止。
3. 折叠页面：在结尾拖动页面折角，看到另一种选择的结果。
4. 留下痕迹：每次选择会更新线条数量、颜色、透明度、文字位置和声景层。
5. 反事实比较：重写只改变选中的页面，原始笔迹永久保留。
6. 心愿路线：把每章第一遍的心愿拼成一条完整路径，展示其风景与价格。

机制上避免传统分数。可以有内部状态，但它们只用于构成独特的视觉和文本组合：

```text
agency       自主感
care         照护投入
visibility   被看见的程度
belonging    关系归属
rest         休息空间
resources    可用资源
```

这些变量不对外显示为“能力值”，也不汇总成好坏结论。

## 6. 技术方案

### 当前阶段：静态艺术游戏

- HTML：语义结构、对话框、表单和无障碍焦点
- CSS：排版、纸张色彩、响应式布局、低干扰动效
- Vanilla JavaScript：状态机、叙事数据、事件委托和本地存档
- Canvas 2D：首页人生图与动态线条
- Web Audio API：无外部音频依赖的低音量声景
- Canvas `toBlob()`：生成个人书页 PNG
- `localStorage`：本机保存，默认不上传用户文字

### 第二阶段：专业化工程结构

当内容和动画继续增加时，迁移到：

```text
Vite + TypeScript
├── DOM / CSS       排版、文本、无障碍
├── SVG             红线、人物、可编辑的结构图
├── Canvas / PixiJS 墨迹、粒子、纸张材质
├── GSAP            叙事时间线、显影和转场
├── XState          剧情状态和重写流程
├── Web Audio API   选择驱动的声景
└── IndexedDB       更大的本地人生档案
```

Three.js 只在需要真实空间、复杂光照或 WebGL 后处理时引入。这个项目的主要艺术力量来自文字、版式和线条，过早使用 3D 会增加维护成本并稀释核心体验。

### 数据结构原则

剧情内容与渲染逻辑分离。每个阶段应当是可验证的数据对象，包含：

- 场景文本与说话者
- 心愿选项
- 行动结果
- 不同资源起点下的条件描述
- 隐藏笔迹
- 可访问性标签和音效 cue

这样可以在不改动渲染器的情况下扩写章节、替换语言或制作展览版。

## 7. 隐私与伦理

- 玩家文字默认只存在浏览器本机。
- 不生成心理标签，不声称预测命运。
- 允许清除进度和文字。
- AI 输入只负责把玩家原话转译成叙事选项，不能替玩家判断。
- 任何公开展示都应由玩家主动决定是否展示结尾文字。

## 8. 部署策略

首选 Vercel 连接 GitHub 仓库 `purerainy2-del/be-me`。当前项目无需构建命令，输出目录为仓库根目录。`index.html` 负责把根路径导向 `game.html`。

推荐工作流：

```text
本地开发与测试 → Git commit → GitHub main → Vercel Preview → Production
```

每次功能开发使用独立分支，视觉或内容变更先通过 Vercel Preview 体验，再合并到 `main`。

## 9. 质量标准

每次发布前至少验证：

- 键盘可以完成完整流程
- `prefers-reduced-motion` 下仍可阅读和操作
- 360px 宽度下没有横向滚动
- 刷新后本地进度可以恢复
- 清除按钮确实删除本机数据
- JavaScript 通过语法检查
- PNG 导出不依赖网络资源
- 任何用户输入都经过 HTML 转义

最终标准不是“功能最多”，而是玩家是否能清楚感到：我先被允许拥有愿望，然后才被邀请面对现实。

更进一步，玩家还应当感到：我可以沿着愿望走，也可以改变心意；两者都不是失败。自由不是免于代价，而是在看清代价后仍能说，这是我选择的路。西西弗的幸福也在这里：石头会滚落，斗争仍然可能充实人的心灵；重要的是，玩家知道自己为何再次推起它。
